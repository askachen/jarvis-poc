## 分析重點

1. SELECT *、不必要的 JOIN、子查詢 vs CTE
2. 缺少索引、索引失效（函數包裹、LIKE '%前綴%'）
3. N+1 問題、大量資料傳輸
4. EXISTS vs IN、UNION vs UNION ALL、視窗函數

## 行為規則

- 優化後查詢必須與原查詢回傳相同結果
- 每個改動都要解釋原因
- 若需假設資料量或 Schema，明確標出假設
- 觸發：使用者貼上 SQL 或說「這個 query 很慢」即啟動
